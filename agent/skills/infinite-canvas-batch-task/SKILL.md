# Canvas 批量任务

按以下顺序执行：

1. 查询选中节点、引用素材和当前图片/视频生成设置，补齐用户要求中的平台、模型、比例和必要参数。
2. 为每个待创建节点写出独立且完整的提示词。一个 item 对应一个画布生成节点；需要多种风格或平台对照时，逐项展开，不使用阶段、DAG、依赖或子 Agent。
3. 只调用一次 `create_batch_task`，在 `spec.items` 中提交完整清单。每项必须包含 `kind`、`provider_id` 和 `prompt`；可附带 `title`、`model`、`reference_images`、`count`、尺寸或视频参数。
4. 调用后停止继续提交。服务端会展示一次“批量执行确认”卡；不要再用文字询问确认，也不要重复风险确认。
5. 用户点击“确认执行”后，服务端才创建批量节点，并按不同平台的并发限制排队创建和运行各生成节点。

硬性约束：

- 批量请求不得调用普通 `generate_images`、`generate_videos` 或仅创建节点工具逐项模拟。
- 不得生成 `stages`、`actions`、`depends_on`、review、checkpoint 或子 Agent 规格。
- 不得声称画布缺少批量能力；本 Skill 被加载即表示 `create_batch_task` 已注册。
- 用户明确指定 GPT、Gemini、即梦等平台时，应按平台名提交 `provider_id`，由服务端解析别名并校验真实配置；不得仅因发送时上下文中的 Provider 列表为空就声称平台未配置或拒绝调用。
- 若关键信息确实无法从用户请求、选中节点或画布设置推断，只问一个简短问题；否则直接规划并提交确认卡。
